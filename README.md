# Генератор вечера · Москва

Сайт собирает план на вечер. Дома: фильм, ужин, занятие. В городе: реальные места и события Москвы с адресом, метро и ссылкой на отзывы в Яндекс Картах.

Сайт бесплатный и живёт сам: GitHub каждый день обновляет афишу и дважды в неделю заново собирает базу мест.

## Как запустить (минут 20, программировать не нужно)

1. **Зарегистрируйтесь на [github.com](https://github.com)**, если аккаунта ещё нет.
2. **Создайте репозиторий.** Кнопка «+» справа вверху → New repository. Имя, например, `vecher`. Обязательно выберите **Public**. Нажмите Create repository.
3. **Включите публикацию сайта.** В репозитории: Settings → Pages → в блоке Build and deployment в списке Source выберите **GitHub Actions**.
4. **Загрузите файлы.** Вкладка Code → ссылка «uploading an existing file». Распакуйте архив и перетащите в окно браузера **всё содержимое папки** (не саму папку). Нажмите Commit changes.
5. **Проверьте, что загрузилась папка `.github`.** Она должна быть видна в списке файлов. На Mac такие папки скрыты, и она могла не попасть в загрузку. Если её нет:
   - Add file → Create new file;
   - в поле имени введите `.github/workflows/update.yml`;
   - откройте файл `workflow-copy.txt` из архива, скопируйте весь текст и вставьте;
   - Commit changes.
6. **Подождите 5–10 минут.** На вкладке Actions появится запуск «Обновление базы и публикация сайта». Зелёная галочка значит, что всё готово.
7. **Откройте сайт.** Адрес будет `https://ВАШ_ЛОГИН.github.io/vecher/`. Он же показан в Settings → Pages.

Если на вкладке Actions GitHub просит разрешить запуск, нажмите зелёную кнопку «I understand my workflows, go ahead and enable them».

## Если что-то пошло не так

- **Красный крестик на вкладке Actions.** Откройте запуск, нажмите на красный шаг и скопируйте текст ошибки. С ним легко понять, что чинить.
- **На сайте написано про «демо-набор».** Значит, источники данных не ответили. Запустите обновление вручную: Actions → «Обновление базы и публикация сайта» → Run workflow. Серверы OpenStreetMap иногда перегружены, со второй попытки обычно получается.
- **Обновить базу прямо сейчас.** Та же кнопка Run workflow.

## Откуда данные и как выбираются места

- **OpenStreetMap**: кафе, рестораны, бары, музеи, театры, кинотеатры, катки, квесты, парки и так далее, плюс станции метро. Обновляется по понедельникам и четвергам.
- **Афиша mos.ru**: события на 10 дней вперёд с ценами, площадками и метро. Обновляется каждый день. Это внутренний адрес сайта mos.ru без официальной документации, поэтому он может измениться без предупреждения.

**Подборки экспертов** (`data/curated.txt`): около 870 ресторанов, баров и кофеен из гида Ultima Guide 2026, премии WhereToEat 2026 и подборки кофеен «Афиши Daily». Такие места отмечены на сайте значком ⭐, предлагаются чаще, а кнопка «Только из гидов и премий» оставляет в еде только их. Скрипт сам находит эти места в OpenStreetMap по названию и адресу, а если не находит, определяет координаты по адресу через геокодер Nominatim и запоминает их в `data/geocache.json`. Список обновляется вручную: допишите или удалите строку в `data/curated.txt`.

Для остальных мест оценок и отзывов в открытых данных нет. Отбор идёт по косвенным признакам:

- заведения, которые в OpenStreetMap никто не правил и не проверял четыре года и больше, выбрасываются: слишком часто они уже закрыты;
- чем свежее правка и чем полнее карточка (сайт, часы работы, статья в Википедии), тем выше место;
- сетевые заведения понижаются.

Бюджет учитывается так: у событий цена настоящая, а у мест это оценка по типу заведения и кухне (кофейня дешевле ресторана, стейк-хаус дороже хинкальной). Настоящие оценки и отзывы открываются по кнопке «Отзывы на Яндекс Картах». Кнопка 🚫 на карточке убирает место из подбора в вашем браузере.

## Аккаунты (Firebase)

Без настройки сайт хранит избранное и параметры в браузере, а перенести их на другое устройство можно кодом в «Настройках». Чтобы включить вход и синхронизацию:

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com).
2. Authentication → Sign-in method: включите Email/Password и Google.
3. Authentication → Settings → Authorized domains: добавьте `ВАШ_ЛОГИН.github.io`.
4. Firestore Database → Create database. Во вкладке Rules вставьте содержимое `firestore.rules` и нажмите Publish.
5. Project settings → Your apps → значок `</>`: зарегистрируйте веб-приложение и скопируйте объект `firebaseConfig` в `firebase-config.js` вместо `null`.

Ключи из `firebaseConfig` не секретные: данные каждого пользователя защищены правилами из `firestore.rules`.

## Что можно поменять самому

- **Идеи для вечера дома**: в `index.html` найдите `const DB = {` и допишите свои фильмы, блюда и занятия по образцу.
- **Сколько мест оставлять в категории**: `LIMITS` и `DEFAULT_LIMIT` в начале `scripts/update_data.py`.
- **Как часто обновлять**: строка `cron` в `.github/workflows/update.yml`.
- **Какие места под какое настроение**: таблица `MOOD_W` в `index.html`.
- **Группы в строке «Что хочется» и список кухонь**: `WANT` и `CUISINES` там же.
